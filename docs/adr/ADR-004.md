# ADR-004 — Modelo híbrido AWS + Caracas; restricciones de servicios

**Estado:** Aceptado  
**Fecha:** 2026-10-15  
**Autor:** Equipo de Plataforma GAITAS  
**Revisores:** Equipo de Seguridad, Actuaría

---

## Contexto

GAITAS debe ejecutarse en infraestructura cloud que sea:

- Conforme con la normativa SUDESEG/SUNACRIP (datos en región controlada, trazabilidad completa).
- Capaz de conectar con el datacenter de Caracas (sistemas core, impresión de pólizas físicas, sistema SAA).
- Portable: sin lock-in a servicios propietarios de un único proveedor.
- Económicamente viable para una aseguradora mediana venezolana con presupuesto en USD limitado.

Se evaluaron tres opciones:

| Opción | Descripción | Resultado |
|--------|-------------|-----------|
| A | 100% AWS managed (EKS + RDS + MSK + Cognito) | **Descartado** — lock-in excesivo, Cognito no portable |
| B | On-prem Caracas únicamente (K3s + PostgreSQL) | **Descartado** — sin elasticidad, riesgo de corte eléctrico/red |
| C | Híbrido: EKS en AWS + K3s en Caracas, VPN sitio a sitio | **Aceptado** |

---

## Decisión

**Opción C:** Infraestructura híbrida con AWS como cloud principal y K3s en Caracas como nodo secundario/edge.

### Restricciones de servicios (hard rules)

Las siguientes restricciones se aplican **en toda la organización** mediante SCP de AWS Organizations:

| Servicio prohibido | Razón |
|--------------------|-------|
| DynamoDB | Lock-in NoSQL; equivalente portable: PostgreSQL 16 |
| Lambda | Lock-in serverless; equivalente portable: Celery workers en K8s |
| SQS | Lock-in queue; equivalente portable: RabbitMQ en K8s |
| Cognito | Lock-in IdP; equivalente portable: Keycloak (OIDC/SAML estándar) |
| IAM Users con claves largas | Riesgo de fuga de credenciales; solo SSO via IAM Identity Center |

### Estado remoto OpenTofu

Se usa bloqueo nativo de S3 (`use_lockfile = true`, OpenTofu ≥ 1.10) en lugar de DynamoDB. El bucket `gaitas-tofu-estado-{cuenta}` tiene Object Lock, versionado y cifrado KMS.

---

## Consecuencias

### Positivas

- Portabilidad: cualquier componente puede migrarse a otro proveedor cloud o a Caracas.
- Sin claves IAM de larga duración: todas las integraciones usan OIDC efímero.
- Cumplimiento normativo: CloudTrail organizacional + Object Lock 7 años cumple Art. 67 LSIB.

### Negativas / Riesgos

| # | Riesgo | Control implementado |
|---|--------|---------------------|
| 1 | Latencia VPN Caracas–AWS | Monitoreo de latencia; datos de salud nunca en caché sin cifrar |
| 2 | Costo NAT gateway | Un solo NAT en nonprod; dos en prod (redundancia AZ) |
| 3 | EKS sin endpoint público | kubectl solo accesible desde VPN o SSM Session Manager |
| 4 | Lock-in suave a EKS | Manifiestos Kubernetes estándar; Argo CD portable a cualquier K8s |
| 5 | Recuperación ante desastre | K3s en Caracas como fallback; RTO 4h, RPO 1h (nivel crítico) |
| 6 | Cumplimiento Art. 67 LSIB | Object Lock COMPLIANCE 7 años en bucket de respaldos |
| 7 | Acceso no autorizado a datos de salud | KMS key separada (`datos-salud`), política restrictiva, nunca en CloudTrail |
| 8 | Datos de salud en logs | `sensible=True` en todos los campos de salud; llave KMS separada |
| 9 | Auditoría insuficiente | CloudTrail organizacional + GuardDuty; alertas SNS en tiempo real |
| 10 | MFA en cuenta raíz | MFA de hardware obligatorio en root; SCP bloquea creación de usuarios IAM |
